# Evaluation

Evaluation block for Harbor-based benchmark rollouts. This block manages the
Live-side shell around a pinned Harbor checkout and stores Harbor jobs, LiteLLM
trajectories, and logs under `artifacts/`. The benchmark dataset is resolved
through Harbor's `registry.json` rather than a locally-staged task directory.

## Operational State

`config.yaml` is the active run profile; it does not contain mutable job status.
Inspect live `harbor` / LiteLLM processes and
`artifacts/jobs/<job>/result.json` for current progress. Archived run records
live in `artifacts/index.yaml`.

## Pipeline

```text
config.yaml task_source (registry-resolved)
    └─▶ Harbor command generated by scripts/start.sh
          └─▶ --dataset <name>@<version> --registry-path repos/harbor/registry.json
                └─▶ artifacts/jobs/<job>/
                      ├─▶ result.json  (job roll-up)
                      ├─▶ <task>/result.json
                      ├─▶ <task>/agent/litellm-trajectory.jsonl
                      ├─▶ <task>/verifier/*  (verdict and test logs)
                      └─▶ analysis/*  (post-eval reports)
```

## Repo Policy

`repos/harbor` is a tracked submodule pinned by
`meta_info.repositories.harbor.commit`. Initialize it with `git submodule
update --init subblock/evaluator/repos/harbor`; use `scripts/update_repos.sh` to
move an existing clean checkout to the configured pin. Never edit the managed
Harbor worktree in place.

## Quick Start

### Step 1: Download Or Update Harbor

```text
Download or update the eval Harbor repository. Use subblock/evaluator/config.yaml, run bash scripts/update_repos.sh, and confirm repos/harbor matches the pinned commit. Do not install environments or launch a job.
```

### Step 2: Install Or Refresh Environments

```text
Install or refresh the eval environments. Use subblock/evaluator/config.yaml and install artifacts/env/harbor-uv plus artifacts/env/litellm-venv. Do not install vLLM on the CPU eval node and do not launch a job.
```

### Step 3: Pick A Benchmark

Edit `config.yaml → runtime_info.input.task_source.dataset_name` (and optionally
`version`). Supported values:

SWE / terminal (validated end-to-end):

- `swebench-verified` @ `1.0` (500 tasks)
- `swebench-verified-100` @ `1.0` (100-task subset)
- `swebench_multilingual` @ `1.0` (300 tasks)
- `swebench_multilingual-100` @ `1.0` (100-task subset, seed=42)
- `swebenchpro` @ `1.0` (731 tasks)
- `swebenchpro-100` @ `1.0` (100-task subset)
- `terminal-bench` @ `2.0` (89 tasks)

Other coding benchmarks:

- `aider-polyglot` @ `1.0` (225 tasks, polyglot code editing)
- `livecodebench` @ `6.0` (100 tasks, competitive programming)
- `humanevalfix` @ `1.0` (164 tasks, bug fixing)
- `bigcodebench-hard-complete` @ `1.0.0` (145 tasks, function-level completion)

No task copy step is needed — Harbor pulls task data from its registry. Pick a
`-100` subset for fast smoke runs.

The active profile uses MODE B (local vLLM). Before validation, run
`scripts/serve_local_model.sh` on the GPU node in its own tmux session and keep
it alive for the full eval. Neither `/evaluator:setup` nor `scripts/start.sh`
installs or launches vLLM.

### Step 4: Validate Current Config

```text
Run the /evaluator:check workflow: execute bash scripts/dryrun.sh, then bash scripts/probe_llm_completion.sh and the live process/port checks. The completion probe is mandatory; GET /models alone can pass while the upstream origin is down. If a check fails, explain how to fix it. Do not modify config.yaml unless I ask.
```

### Step 5: Launch A Job

```text
Run an eval Harbor job using the current subblock/evaluator/config.yaml. First complete /evaluator:check, present the validated run summary, and wait for explicit confirmation. Only then run bash scripts/start.sh.
```

```text
The eval Harbor job was interrupted. Verify whether scripts/start.sh's EXIT trap cleaned up its per-job LiteLLM proxy. Stop only the process owned by this job; do not kill unrelated LiteLLM or vLLM processes.
```

### Step 6: Inspect Results

Expected trajectory files are under
`artifacts/jobs/<job>/<task>/agent/litellm-trajectory.jsonl`. Job and trial
status live in `result.json`; per-task verdicts and test logs live under
`<task>/verifier/`. Post-eval reports live under `<job>/analysis/`.

```text
Inspect the latest eval job under artifacts/jobs. Summarize resolved, failed, error, and in-flight counts from the job-level and per-trial result.json files. Use bash dashboard/start.sh for the web view; do not write runtime status into config.yaml.
```

### Step 7: Create A Config Variant

```text
Create a new eval config variant for <benchmark/model/agent/concurrency>. Do not overwrite config.yaml. Save the variant next to config.yaml with a descriptive name and explain the changed fields.
```
