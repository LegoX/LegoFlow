# Inputs & Outputs

## Inputs

Defined in `config.yaml`. `evaluator` uses `config.yaml` rather than `inputs.yaml`
because the file describes a full Harbor evaluation profile, not only upstream
inputs.

| Name | Description | Source | Required |
|---|---|---|---|
| repositories | Git remote/ref/path/read-only policy for Harbor | external | yes |
| environment | Harbor uv env and LiteLLM runtime versions | external | yes |
| llm_api | Raw upstream model API used by LiteLLM | external | yes |
| litellm_proxy | LiteLLM template, port, and master key | external | yes |
| task_source | Benchmark selection: provider=harbor_registry, dataset_name, version, registry_path | external | yes |
| harbor_job | jobs_dir, concurrency, retries, timeout, smoke cap | external | yes |
| agent | Harbor agent, version, runtime image, sampling controls | external | yes |

## Active Runtime Values

Excerpted from `config.yaml`; treat that file as the source of truth before
launching a job.

```yaml
repositories:
  harbor:
    url: git@github.com:SWE-Lego/harbor.git
    branch: main
    commit: 149e75770f8c369d6fae31c158ea761d676b4d3a   # latest harbor commit
    path: repos/harbor
    readonly: true
environment:
  harbor_uv: artifacts/env/harbor-uv
  litellm_uv: artifacts/env/litellm-venv
  litellm:
    python_version: "3.13"
    litellm_version: "1.83.14"
llm_api:
  model: "openai/MiniMax-M2.7"
  api_base_url: "http://llm10.jierungogogo.com/v1"
  api_key: "dummy-key"
litellm_proxy:
  config_template: scripts/serve_llm/litellm_config.example.yaml
  port: 4101
  master_key: dummy-key-cf
task_source:
  provider: harbor_registry
  dataset_name: swebench-verified   # SWE/terminal: swebench-verified[-100] | swebench_multilingual[-100] | swebenchpro[-100] | terminal-bench
                                    # Other coding: aider-polyglot | livecodebench | humanevalfix | bigcodebench-hard-complete
  version: "1.0"                    # terminal-bench → "2.0", livecodebench → "6.0", bigcodebench-hard-complete → "1.0.0"
  registry_path: repos/harbor/registry.json
harbor_job:
  jobs_dir: artifacts/jobs
  n_concurrent: 6
  n_tasks: null        # null = full benchmark
  max_retries: 2
  timeout_multiplier: 1
agent:
  name: custom-claude-code
  version: 2.1.118
  runtime_image: docker.io/jierun/c-cc-2.1.118:v0.1
  max_turns: 200
  temperature: 0.7
```

`scripts/start.sh` derives stable defaults: `producer_block=evaluator`,
`output_format=litellm_logger_v0.1`, the custom Claude Code import path, runtime
mount paths, and LiteLLM trajectory header. It also writes a per-job LiteLLM
config under `artifacts/litellm/<job>/` and passes it to Harbor's LiteLLM serve
script through `LITELLM_CONFIG` before launching the job.

## Outputs

This block does not maintain a separate `outputs.yaml`. The handoff contract is
declared in `config.yaml`:

- `harbor_job.jobs_dir`: Harbor job output root under this block's artifacts
- generated LiteLLM config: `artifacts/litellm/<job>/litellm_config_evaluator.yaml`
- `harbor_job.jobs_dir/<job>`: generated Harbor job directory
- `{job_dir}/<task-id>/agent/litellm-trajectory.jsonl`: LiteLLM logger trajectory
- `{job_dir}/<task-id>/evaluation/`: per-task verdict, scoring, test logs

## Config Variants

`config.yaml` is the active run profile. For per-benchmark or per-model variants,
copy `config.yaml` to a sibling file (e.g. `config.terminal-bench-2-glm5.yaml`)
and only replace `config.yaml` when you are ready to make that variant active.

Each launched job receives a snapshot of the active config at:

```text
artifacts/jobs/<job>/config.yaml
```
