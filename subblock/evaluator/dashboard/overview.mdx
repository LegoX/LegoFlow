# Evaluator

Evaluator block for Harbor-based benchmark rollouts. This block manages the
Live-side shell around a pinned Harbor checkout and stores Harbor jobs, LiteLLM
trajectories, and logs under `artifacts/`. The benchmark dataset is resolved
through Harbor's `registry.json` rather than a locally-staged task directory.

## Operational State

The active operational snapshot lives in `config.yaml → status`. Use that for
the current phase, active job, blockers, and operator next steps; this overview
stays focused on the stable workflow.

## Pipeline

```text
config.yaml task_source (registry-resolved)
    └─▶ Harbor command generated by scripts/start.sh
          └─▶ --dataset <name> --registry-path repos/harbor/registry.json
                └─▶ artifacts/jobs/<job>/
                      ├─▶ <task>/agent/litellm-trajectory.jsonl
                      └─▶ <task>/evaluation/*  (per-benchmark results)
```

## Repo Policy

`repos/harbor` is local-only and gitignored. It is updated through
`scripts/update_repos.sh`, not committed into this repository.

## Quick Start

### Step 1: Download Or Update Harbor

```text
Download or update the evaluator Harbor repository. Use subblock/evaluator/config.yaml, run bash scripts/update_repos.sh, and confirm repos/harbor matches the pinned commit. Do not install environments or launch a job.
```

### Step 2: Install Or Refresh Environments

```text
Install or refresh the evaluator environments. Use subblock/evaluator/config.yaml, install artifacts/env/harbor-uv and artifacts/env/litellm-venv, then run bash scripts/dryrun.sh. Do not launch a job.
```

### Step 3: Pick A Benchmark

Edit `config.yaml → runtime_info.input.task_source.dataset_name` (and optionally
`version`). Supported values:

SWE / terminal (validated end-to-end):

- `swebench-verified` @ `1.0` (500 tasks)
- `swebench-verified-100` @ `1.0` (100-task subset)
- `swebench_multilingual` @ `1.0` (300 tasks)
- `swebench_multilingual-100` @ `1.0` (100-task subset, seed=42)
- `swebenchpro` @ `1.0` (731 tasks)
- `swebenchpro-100` @ `1.0` (100-task subset)
- `terminal-bench` @ `2.0` (89 tasks)

Other coding benchmarks:

- `aider-polyglot` @ `1.0` (225 tasks, polyglot code editing)
- `livecodebench` @ `6.0` (100 tasks, competitive programming)
- `humanevalfix` @ `1.0` (164 tasks, bug fixing)
- `bigcodebench-hard-complete` @ `1.0.0` (145 tasks, function-level completion)

No task copy step is needed — Harbor pulls task data from its registry. Pick a
`-100` subset for fast smoke runs.

### Step 4: Validate Current Config

```text
Validate subblock/evaluator/config.yaml with bash scripts/dryrun.sh. If it fails, explain which requirement is missing and how to fix it. Do not modify config.yaml unless I ask.
```

### Step 5: Launch A Job

```text
Run an evaluator Harbor job using the current subblock/evaluator/config.yaml. First run bash scripts/dryrun.sh; only if it passes, run bash scripts/start.sh.
```

```text
The evaluator Harbor job has finished, but the LiteLLM proxy may still be running. Find the LiteLLM process started for this evaluator job and stop it safely. Do not kill unrelated LiteLLM processes.
```

### Step 6: Inspect Results

Expected trajectory files are under
`artifacts/jobs/<job>/<task>/agent/litellm-trajectory.jsonl`. Per-task evaluation
artifacts (verdicts, test logs) live under `artifacts/jobs/<job>/<task>/evaluation/`.

```text
Inspect the latest evaluator job under artifacts/jobs. Summarize pass/fail counts and update status in subblock/evaluator/config.yaml.
```

### Step 7: Create A Config Variant

```text
Create a new evaluator config variant for <benchmark/model/agent/concurrency>. Do not overwrite config.yaml. Save the variant next to config.yaml with a descriptive name and explain the changed fields.
```
