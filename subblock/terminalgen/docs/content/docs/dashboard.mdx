title: Dashboard
description: Monitor Terminal-gen progress
---

Terminal-gen ships a local progress dashboard generator at:

```text
subblock/terminalgen/dashboard/progress_monitor_all.py
```

It reads this block's `artifacts/terminal_tasks/{domain}-tl/` and
`artifacts/collected_questions/`, then writes a static HTML summary and appends
a snapshot to a JSONL state file.

## Generate locally

```bash
python3 subblock/terminalgen/dashboard/progress_monitor_all.py \
  --output-html subblock/terminalgen/dashboard/site/index.html \
  --state-file subblock/terminalgen/dashboard/memory/.progress_monitor_all_state.jsonl \
  --cache-file subblock/terminalgen/dashboard/memory/.progress_monitor_all_cache.json
```

Or serve it:

```bash
python3 subblock/terminalgen/dashboard/progress_monitor_all.py --serve --port 8000
```

## What it monitors

| Source | Files | Shown as |
| --- | --- | --- |
| Question buckets | `collected_questions/<domain>_so_data.json` | Scraped question counts per domain |
| Candidates | `terminal_tasks/<domain>-tl/_candidates/s*/task_*` | Generated task counts |
| Verified manifests | `terminal_tasks/<domain>-tl/verifiable_tasks.txt` | Validated task totals |
| (derived) | verified / generated | Per-domain pass rate |

## Optional Cloudflare Pages sync

`subblock/terminalgen/dashboard/run_cloudflare_pages_sync.sh` loops the generator
and deploys `site/` to a Cloudflare Pages project (`terminalgen-databoard` by
default). It is **off by default** — configure
`~/.config/terminalgen_progress_cloudflare.env` and run it only when you want a
hosted board. See `dashboard/README.md`.

Use the docs when onboarding or reviewing the pipeline; use the dashboard when
operating a live data construction run.
