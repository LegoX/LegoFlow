`terminalgen` is a data-curation stage **parallel to curator**: where curator builds verified SWE tasks from GitHub PRs, terminalgen builds verified **terminal** tasks from StackOverflow Q&A. It wraps the pinned, read-only [terminal-lego](https://github.com/SWE-Lego/terminal-lego) pipeline (scrape → generate → validate) and groups tasks into 13 domains. Its output feeds the same downstream chain (tracer → trainer → evaluator).

Full docs: **[terminalgen-docs.pages.dev/docs](https://terminalgen-docs.pages.dev/docs)**

## At a glance

- **Inputs**: `so_api_key` (StackExchange), `llm_api` (api_key, api_base_url, gen_model).
- **Output**: verified tasks (terminal-lego v1.0) under `subblock/terminalgen/artifacts/terminal_tasks/{domain}-tl/`, gated by `verifiable_tasks.txt` (only task IDs there passed Docker validation, reward=1.0). `extract_verified_tasks.py` optionally flattens them into `artifacts/merged_terminal_tasks/` (same format).
- **Runs**: Local (CPU + Docker). Long-running — minutes-to-hours per domain.

## How to run

```text
/terminalgen:setup     # init terminal-lego submodule, build env, verify keys
/terminalgen:check     # preflight: SO key, LLM endpoint, Docker, schema
/terminalgen:run       # pipeline: scrape → generate → Docker-validate (optional separate flat-merge step)
/terminalgen:dashboard # progress dashboard
```
