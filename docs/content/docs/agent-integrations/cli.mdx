# LegoFlow CLI

Claude Code and Codex use the same `legoflow` command interface. Agent-specific plugins provide the user-facing instructions, while the CLI dispatches to the existing block scripts.

## Installation

Run the CLI from a checkout:

```bash
export PATH="$PWD/bin:$PATH"
```

You can also invoke it directly as `./bin/legoflow`.

## Agent plugin installation

Claude Code and Codex use different local plugin mechanisms, but expose the
same LegoFlow commands.

### Claude Code

Register the five Claude Code plugin directories as local marketplaces and
install their plugins:

```bash
claude plugin marketplace add ./.claude/plugins
claude plugin marketplace add ./blocks/curator/.claude/plugins
claude plugin marketplace add ./blocks/tracer/.claude/plugins
claude plugin marketplace add ./blocks/trainer/.claude/plugins
claude plugin marketplace add ./blocks/evaluator/.claude/plugins

claude plugin install root@root-block
claude plugin install curator@curator-block
claude plugin install tracer@tracer
claude plugin install trainer@trainer-block
claude plugin install evaluator@evaluator-block
```

Run `/reload-plugins` or restart Claude Code after installation.

### Codex

Codex loads plugins from a configured marketplace and requires an explicit
installation. Register the repository root as the local LegoFlow marketplace,
then install the plugins you want:

```bash
cd LegoFlow
codex plugin marketplace add .
codex plugin add root@legoflow
codex plugin add curator@legoflow
codex plugin add tracer@legoflow
codex plugin add trainer@legoflow
codex plugin add evaluator@legoflow
```

Restart Codex after installation. The marketplace manifest is
`.agents/plugins/marketplace.json`; its paths are relative to the repository
root.

The five Codex plugins are:

```text
plugins/root/
plugins/curator/
plugins/tracer/
plugins/trainer/
plugins/evaluator/
```

Each plugin has a `.codex-plugin/plugin.json` manifest and a `skills/` folder.
Every Codex skill references the corresponding Claude Code skill, which remains
the canonical workflow definition. This keeps behavior, safety gates, and
reporting consistent between the two agents.

## Commands

| Command | Purpose |
| --- | --- |
| `legoflow check` | Check the root configuration and dependencies |
| `legoflow check --full` | Check the root and every block |
| `legoflow check <block>` | Check one block |
| `legoflow setup <block>` | Prepare one block's repositories and environment |
| `legoflow run` | Run the root pipeline |
| `legoflow run <block>` | Run one block |
| `legoflow dashboard <block>` | Inspect or serve one block dashboard |
| `legoflow create` | Show the shared block-creation contract for an agent-assisted scaffold |

The canonical LegoFlow CLI command form is slash-based:

```text
/root:check
/curator:check
/curator:collect-prs
/tracer:run
/trainer:run
/evaluator:dashboard
```

The repository CLI accepts these exact strings as arguments:

```bash
./bin/legoflow /root:check
./bin/legoflow /curator:check
./bin/legoflow /tracer:run
```

Claude Code exposes these commands as slash commands. Codex does not map
project skills to Claude-style slash commands; after installation, invoke the
unique Codex skills as `$root-check`, `$curator-check`, `$curator-run`,
`$tracer-run`, `$trainer-run`, or `$evaluator-run`, or describe the desired
workflow in natural language. Both agents execute the same canonical Claude
workflow through the shared CLI.
| `legoflow collect-prs` | Collect Curator candidate pull requests |
| `legoflow create-tasks` | Create and verify Curator tasks |

Use `--` before script-specific options when needed, for example `legoflow run tracer -- --no-dryrun`.

## Agent parity

Claude Code and Codex use the same action names and the same CLI commands:

| Action | Claude Code | Codex | Shared execution |
| --- | --- | --- | --- |
| Curator check | `/curator:check` | `$curator-check` | `legoflow /curator:check` |
| Curator PR collection | `/curator:collect-prs` | `$curator-collect-prs` | `legoflow /curator:collect-prs` |
| Tracer run | `/tracer:run` | `$tracer-run` | `legoflow /tracer:run` |
| Trainer run | `/trainer:run` | `$trainer-run` | `legoflow /trainer:run` |
| Evaluator dashboard | `/evaluator:dashboard` | `$evaluator-dashboard` | `legoflow /evaluator:dashboard` |

`create` remains agent-assisted because block scaffolding requires an intake conversation. Both agents use the same contract and must produce the same files; `legoflow create` prints that contract and the validation command.

Both agents must still follow `check -> confirm -> run`. The CLI does not bypass user confirmation or change the underlying Harbor, training, or evaluation runtime.
