title: Motivation
description: Why we built SWE-Lego-Live
---

Training a strong coding agent is a multi-stage pipeline — curate tasks, roll out trajectories, do SFT, then RL. Each stage needs its own data, its own environment, and its own GPUs, and the handoffs between them quietly break every time someone runs them by hand.

We built **SWE-Lego-Live** so the whole pipeline behaves like one project. Every stage is a self-contained **block** with the same shape — a `config.yaml`, a `scripts/start.sh`, an `artifacts/` tree — wired into a parent by name. Run one block, run the whole tree, or swap a block out; the contracts hold.

![SWE-Lego-Live pipeline motivation](/figures/my-version.png)

The diagram starts from **objective tasks**: generate SWE trajectory data, improve terminal-agent capability, and support longer end-to-end tasks. Those objectives enter the **root block**, which is the orchestration layer for the whole project. The root block exposes the plugin commands (`/<block>:setup`, `/<block>:check`, `/<block>:run`, and dashboard views), resolves the config tree, dispatches block runs, and archives run state.

Under the root block, each pipeline stage is represented as a block with the same internal contract:

```text
GitHub PRs ─▶ curator ─▶ tracer ─▶ trainer ─▶ rl
```

The figure makes the handoffs explicit. **curator** collects PRs and creates SWE tasks; **tracer** rolls out task trajectories; **trainer** turns verified trajectories into checkpoints; the final evaluation/RL stage consumes checkpoints and produces reports or policy updates. The arrows between blocks are typed artifacts (`tasks`, `trajectories`, `ckpt`) rather than informal paths copied by hand.

Two support layers keep the pipeline inspectable and reproducible. **dashboards** publish per-block run state, artifacts, logs, and metrics. **repositories** pin the external code each block depends on, so a run archive can explain not only what happened, but which repo versions produced it.

This is why the block abstraction matters: every stage can be developed independently, but the root block can still compose them as one system. See [Block Design](/docs/block-design) for the exact block anatomy.

SWE-Lego-Live provides:

- A **block abstraction** that makes every pipeline stage swappable, restartable, and replayable
- **curator** — curated SWE tasks generated and NOP/Oracle-verified directly from GitHub PRs
- **tracer** — containerized agent rollouts at scale on Harbor, with pluggable agent scaffolds
- **trainer** — supervised fine-tuning on the resulting trajectories (LLaMA-Factory + DeepSpeed ZeRO-3)
- **rl** — online RL on SWE-bench through Harbor + vLLM + verl
- **Per-run archives** with config, scripts, and repo SHAs frozen for every execution
- **A Claude Code plugin** (`/root:check`, `/root:run`, `/root:create`) that drives the tree end-to-end
