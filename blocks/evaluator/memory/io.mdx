# Inputs & Outputs

## Inputs

Defined in `config.yaml`. `evaluator` uses `config.yaml` rather than `inputs.yaml`
because the file describes a full Harbor evaluation profile, not only upstream
inputs.

| Name | Description | Source | Required |
|---|---|---|---|
| repositories | Git remote/ref/path/read-only policy for Harbor | external | yes |
| environment | Harbor uv env and LiteLLM runtime versions | external | yes |
| llm_api | Raw upstream model API used by LiteLLM | external | yes |
| local_model_serving | GPU-node checkpoint path and served model name for local vLLM mode | external | when using local mode |
| litellm_proxy | LiteLLM template, port, and master key | external | yes |
| task_source | Benchmark selection: provider=harbor_registry, dataset_name, version, registry_path | external | yes |
| harbor_job | jobs_dir, concurrency, retries, timeout, smoke cap | external | yes |
| job_analysis | Post-eval analysis toggle and metadata-tagging endpoint | external | no |
| agent | Harbor agent, version, runtime image, sampling controls | external | yes |

`scripts/start.sh` derives stable defaults: `producer_block=evaluator`,
`output_format=litellm_logger_v0.1`, the selected agent's import path and API
protocol, runtime mount paths, and LiteLLM trajectory header. It also writes a
per-job LiteLLM config under `artifacts/litellm/<job>/` and passes it to
Harbor's LiteLLM serve script through `LITELLM_CONFIG` before launching the
job.

## Outputs

This block does not maintain a separate `outputs.yaml`. The handoff contract is
declared in `config.yaml`:

- `harbor_job.jobs_dir`: Harbor job output root under this block's artifacts
- generated LiteLLM config: `artifacts/litellm/<job>/litellm_config_evaluator.yaml`
- `harbor_job.jobs_dir/<job>`: generated Harbor job directory
- `{job_dir}/config.yaml`: snapshot of the active eval profile
- `{job_dir}/result.json`: job-level Harbor roll-up
- `{job_dir}/<task-id>/result.json`: per-trial status and reward
- `{job_dir}/<task-id>/agent/litellm-trajectory.jsonl`: LiteLLM logger trajectory
- `{job_dir}/<task-id>/verifier/`: per-task verdict, scoring, and test logs
- `{job_dir}/analysis/`: post-eval attribution and scoring reports

## Config Variants

`config.yaml` is the active run profile. For per-benchmark or per-model variants,
copy `config.yaml` to a sibling file (e.g. `config.terminal-bench-2-glm5.yaml`)
and only replace `config.yaml` when you are ready to make that variant active.

Each launched job receives a snapshot of the active config at:

```text
artifacts/jobs/<job>/config.yaml
```
