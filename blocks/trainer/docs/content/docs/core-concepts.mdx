---
title: Core Concepts
---

Trainer has the following core concepts:

## Trajectory

A **trajectory** is the complete, replayable log of one agent rollout — the raw material Trainer trains on. Tracer produces them per task under a Harbor `job_dir`:

```text
artifacts/jobs/<job>/<task>/agent/litellm-trajectory.jsonl
```

Trainer does not author trajectories — it consumes a `job_dir` of them, wired from the upstream `tracer` block via `meta_info.dependencies.from` (mirrored by Tracer's own `dependencies.to`).

## Scaffold

A **scaffold** is the agent harness that produced a trajectory — Claude Code, OpenCode, OpenHands SDK, or Terminus-2. The scaffold determines the raw trajectory shape, which selects the `swe_data_process` converter used to turn it into training data. See [Scaffolds](/docs/data-pipeline/scaffolds).

## IM format (intermediate)

**IM** is the intermediate representation: OpenAI-style messages with `tool_calls`, one JSONL row per trajectory, in PangUML v2 shape. Per-instance metadata (`_instance_id`, `_agent_type`, `_score`) is stored under `meta_info.unique_info`. Conversion to IM auto-invokes rule scoring, so every IM row carries a quality score. See [Scoring](/docs/data-pipeline/scoring).

## LF format (LLaMA-Factory)

**LF** is the training-ready representation: ShareGPT-style messages in JSON. Harbor conversion writes it to `artifacts/data/lf_data/<dataset>.json`; an exact Hub file is cached under `artifacts/data/hf_data/`, while a Hub dataset config can be loaded directly. This is what LLaMA-Factory consumes.

## Dataset registration

Before training, the selected LF source is registered in LLaMA-Factory's `dataset_info.json` under a **dataset name** (derived from `conversion.data_name`). The entry points to a local `file_name` for converted, local, and exact-Hub-file sources, or to `hf_hub_url` for whole dataset-config loading. This is STEP 1 of `scripts/train.sh`.

## Run

A **run** is one execution of the pipeline driven by a single `config.yaml`: obtain/convert LF data → register → train. Each run writes its checkpoints and logs to `artifacts/model/<run>/`, where `<run>` is `training.output_dir` (a relative value resolves to `artifacts/model/<basename>`). Run history is appended to `artifacts/index.yaml` by `scripts/archive_run.sh`.

## Checkpoint

A **checkpoint** is a saved model state under `artifacts/model/<run>/checkpoint-<step>/`. With `save_strategy: steps` it is written every `save_steps`; with `save_strategy: epoch` it is written at epoch boundaries. The latest checkpoint path is recorded in `config.yaml` → `runtime_info.output.checkpoint_path` and is the block's primary handoff to downstream consumers (`rl`, `evaluator`).

## Repo exclusion filter

`scripts/excluded_repos.txt` lists `owner/repo` entries from the SWE-bench benchmark sets (Verified, Pro, Multilingual). All converters filter these out by default so eval repos never leak into training data. Regenerate it with `scripts/generate_excluded_repos.py`; disable per-experiment with `--exclude-repos-file ""`.
