# Terminal Curator

Builds bounded batches of Harbor terminal tasks from Stack Overflow, saved
questions JSON, or local candidate tasks. It is a sibling of SWE Curator and
feeds the same Tracer pipeline.

## Operational state

This tracked page describes the block; it is not a live run record. Read
`artifacts/state.json` for live phase/counts,
`artifacts/reports/latest.json` for completed per-task evidence,
`artifacts/tasks/verifiable_tasks.txt` for published IDs, and
`artifacts/index.yaml` for archived runs. Missing files on a fresh checkout
mean the block has not run yet.

## Acceptance gate

Each published task has a Harbor-valid layout and independent fresh-container
validation with Oracle reward 1 and NOP reward 0. Generation success, an
upstream review, or a directory count is not a substitute for this evidence.
Tracer must then run an actual solving agent to establish successful rollout.

## Operator path

1. Fill the source, finite limits, endpoint/model, and resource host in
   `config.yaml`; use environment variables for credentials.
2. Use `:setup`, `:check`, then the authorized `:run`.
3. Open `:dashboard` and inspect candidate failures as well as verified count.
4. Select `terminal-curator` in Tracer's `task_source.local_block`, check
   Tracer, and launch its separately authorized rollout.

See `docs/content/docs/getting-started.mdx` for the configuration and commands.
