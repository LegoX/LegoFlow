---
title: Configuration Guide
---

Tracer config controls rollout jobs: which tasks to run, which agent scaffold
to use, how many jobs to launch, and whether to convert trajectories for SFT.
Most runs only need a few `runtime_info.input` fields. Leave `meta_info`,
repository pins, environment paths, and output declarations alone unless you are
changing the block contract itself.

## Common fields

| Area | Edit when | Main fields |
| --- | --- | --- |
| Model endpoint | You want Tracer to call a different model or gateway. | `llm_api.api_key`, `api_base_url`, `model` |
| Task source | You are receiving SWE/terminal tasks, an external local pool, or an HF snapshot. | `task_source.provider`, `local_block`, `dataset_name`, `terminal_tasks_dir`, `split` |
| Rollout scale | You are doing a smoke run, a batch run, or a full production run. | `harbor_job.n_tasks`, `n_concurrent`, `max_retries`, `timeout_multiplier` |
| Agent scaffold | You switch between Claude Code, OpenCode, or OpenHands SDK. | `agent.name`, `version`, `runtime_image`, `runtime_host_path` |
| Remote machine | You want Tracer to run rollouts on another Docker server. | `meta_info.resources.ip`, `user`, `pwd`, `directory` |
| Trainer handoff | You need training-ready data after rollout. | `sft_conversion.enabled`, `scaffold`, `tokenizer_name`, `out_dir` |

## An example reference

Start with local Curator output, a small task cap, Claude Code, and SFT
conversion enabled. This gives you a complete mini-run that can hand data to
Trainer.

<ConfigSnippet title="blocks/tracer/config.yaml">
{"runtime_info:\n  input:\n    llm_api:\n      api_key: <YOUR_API_KEY>\n      api_base_url: https://your-openai-compatible-endpoint/v1\n      model: openai/Qwen3.6-35B-A3B\n\n    task_source:\n      provider: local\n      dataset_name: ../curator/artifacts/merged_swe_tasks\n      split: train\n\n    harbor_job:\n      jobs_dir: artifacts/jobs\n      n_concurrent: 4\n      n_tasks: 10\n      max_retries: 2\n      timeout_multiplier: 5\n\n    agent:\n      name: custom-claude-code\n      version: 2.1.118\n      runtime_image: docker.io/jierun/c-cc-2.1.118:v0.1\n      runtime_host_path: artifacts/agent-runtime/claude-code\n      max_turns: 80\n      temperature: 0.7\n\n    sft_conversion:\n      enabled: true\n      scaffold: auto\n      tokenizer_name: Qwen/Qwen3.5-35B-A3B-Base\n      out_dir: artifacts/sft_data"}
</ConfigSnippet>

Use `/tracer:check` after editing. It catches missing task sources, bad model
endpoints, unavailable Docker/runtime images, and conversion config mistakes
before `/tracer:run` spends tokens.

## Configuration breakdown

### Remote execution

Tracer runs locally by default. If you want rollouts to happen on a remote
CPU/Docker node, fill `meta_info.resources` so the operating skill knows where
to log in and which block directory to use.

<ConfigSnippet title="blocks/tracer/config.yaml">
{"meta_info:\n  resources:\n    ip: 203.0.113.12              # local = current machine; otherwise SSH target\n    user: ubuntu               # SSH user for the remote server\n    pwd: null                  # prefer SSH keys or your private secret channel\n    directory: /home/ubuntu/LegoFlow/blocks/tracer\n    public_storage: null"}
</ConfigSnippet>

Use a remote node when local Docker capacity, network placement, or long-running
rollouts make the current machine inconvenient. The remote directory should
point at the Tracer block checkout, not just the repository root.

### Task source

Tracer accepts Harbor task pools from the selected local producer, an external local directory, or a prebuilt Hugging Face snapshot. `TRAJGEN_CONFIG` selects a complete private profile; relative profile filenames resolve from this block. An omitted `local_block` keeps the SWE `curator` default; explicit invalid selectors are rejected.

- From Curator Tasks:

<ConfigSnippet title="blocks/tracer/config.yaml">
{"runtime_info:\n  input:\n    task_source:\n      provider: local\n      dataset_name: ../curator/artifacts/merged_swe_tasks\n      split: train"}
</ConfigSnippet>


- From Terminal Curator:

<ConfigSnippet title="blocks/tracer/config.local.yaml">
{"runtime_info:\n  input:\n    task_source:\n      provider: local\n      local_block: terminal-curator\n      terminal_tasks_dir: ../terminal-curator/artifacts/tasks\n    harbor_job:\n      n_tasks: 2\n      n_concurrent: 1\n      max_retries: 0\n"}
</ConfigSnippet>

Terminal input uses `terminal_tasks_dir`, leaving the SWE `dataset_name` intact.
Its independent dependency edge is active only for
`{task_source.provider: local, task_source.local_block: terminal-curator}` and
consumes `terminal-curator.output.harbor_tasks_dir`. A nonempty manifest is
required; missing or invalid listed tasks fail preparation. Before inference,
the producer skill must audit instruction/tests/reference-solution semantics,
record corrections, then repeat fresh Oracle/NOP validation. A runtime pass or
manifest alone does not prove that audit.

For an unrelated local pool, set `local_block: external` and `dataset_name`;
this selects neither producer. For local sources, a manifest filters IDs when
present; sources outside the terminal contract retain the valid-directory
fallback when absent.

- From Hugging Face Task Dataset:

<ConfigSnippet title="blocks/tracer/config.yaml">
{"runtime_info:\n  input:\n    task_source:\n      provider: huggingface\n      dataset_name: Lego-X/<dataset-name>\n      split: train"}
</ConfigSnippet>

HF preparation downloads a raw prebuilt-task snapshot. `split` participates in
profile/cache identity but does not filter a dataset-library split here.

### Staging ownership and refresh

The public `harbor_job.dataset_path` defaults to `artifacts/tasks/<dataset>`
(`terminal-curator` for terminal input). `harbor_job.dataset` can override the
dataset label. Preparation atomically points the public path at an owned version
under `artifacts/tasks/.legoflow-staging-v1/`, keyed by resolved source, manifest,
settings, and file metadata. `start.sh` uses the fixed version returned by that
invocation, even if another preparation advances the public pointer.

Local task directories remain links. Terminal links resolve to immutable producer
batches; mutable external/SWE contents may still change in place. HF files are
materialized copies and a matching owned copy can be reused without download;
`prepare_tasks.sh --overwrite` requests a fresh download. An existing real
dataset directory or unrelated symlink is never replaced, including with that
flag. Choose a fresh `dataset_path`, or move old staging yourself after checking
active jobs. Retained versions are removed only by explicit cleanup, so preserve
versions referenced by active jobs.

### Smoke run

Use a small `n_tasks` and low concurrency when checking a new endpoint,
runtime image, or task source. This is usually helpful for debugging or getting familiar with the whole pipeline.

<ConfigSnippet title="blocks/tracer/config.yaml">
{"runtime_info:\n  input:\n    harbor_job:\n      n_concurrent: 1\n      n_tasks: 5\n      max_retries: 0\n      timeout_multiplier: 5"}
</ConfigSnippet>

### Production rollout

For production, raise concurrency only after `/tracer:check` passes and a smoke
run has produced valid trajectories.

<ConfigSnippet title="blocks/tracer/config.yaml">
{"runtime_info:\n  input:\n    harbor_job:\n      n_concurrent: 8\n      n_tasks: null             # run every staged task\n      max_retries: 2\n      timeout_multiplier: 5"}
</ConfigSnippet>

## Agent version presets

The agent fields move as a set. Pick one row and keep `agent.name`,
`agent.version`, `agent.runtime_image`, `agent.runtime_host_path`, and
`sft_conversion.scaffold` aligned.

| Scaffold | `agent.name` | `agent.version` | `agent.runtime_image` | `agent.runtime_host_path` | `sft_conversion.scaffold` |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `custom-claude-code` | `2.1.118` | `docker.io/jierun/c-cc-2.1.118:v0.1` | `artifacts/agent-runtime/claude-code` | `claude_code` or `auto` |
| OpenCode | `custom-opencode` | `1.18.7` | `docker.io/jierun/c-oc-1.18.7:v0.1` | `artifacts/agent-runtime/opencode` | `open_code` or `auto` |
| OpenHands SDK | `custom-openhands-sdk` | `1.33.0` | `docker.io/jierun/c-oh-sdk-1.33.0:v0.1` | `artifacts/agent-runtime/openhands-sdk` | `openhands_sdk` or `auto` |

Use `auto` for a fresh run that uses the same `agent.name` in the current
config. Use an explicit scaffold key when reconverting an older job whose
scaffold may differ from the current config.

## Handoff with neighboring blocks

Tracer normally receives tasks from Curator and sends converted LF data to
Trainer.

### Receive Curator tasks

`task_source.dataset_name` is the path Tracer actually reads. The dependency
entry documents that this value comes from Curator's `merged_tasks_dir`, so
root-level checks can validate the handoff.

<ConfigSnippet title="blocks/tracer/config.yaml">
{"meta_info:\n  dependencies:\n    from:\n      task_source.dataset_name:\n        from: curator.output.merged_tasks_dir\n        when: {task_source.provider: local, task_source.local_block: curator}\n\nruntime_info:\n  input:\n    task_source:\n      provider: local\n      dataset_name: ../curator/artifacts/merged_swe_tasks"}
</ConfigSnippet>

### Produce Trainer-ready data

Trainer usually reads `artifacts/sft_data/<job>/lf.json`. Keep conversion on
when Tracer should produce that file after rollout.

<ConfigSnippet title="blocks/tracer/config.yaml">
{"runtime_info:\n  input:\n    sft_conversion:\n      enabled: true\n      scaffold: auto\n      tokenizer_name: Qwen/Qwen3.5-35B-A3B-Base\n      out_dir: artifacts/sft_data\n\n  output:\n    sft_data_dir:\n      path: artifacts/sft_data\n      trajectory_format: artifacts/sft_data/<job>/lf.json"}
</ConfigSnippet>

## Field reference

| Field | Required? | Default | When to change |
| --- | --- | --- | --- |
| `llm_api.api_key` | Yes | `""` | Supply `OPENAI_API_KEY` or use a private config. Never commit it. |
| `llm_api.api_base_url` | Yes | `""` | Supply `OPENAI_API_BASE_URL` for your OpenAI-compatible endpoint. |
| `llm_api.model` | Yes | `openai/Qwen3.6-35B-A3B` | Change when testing a different teacher model. |
| `litellm_proxy.port` | Yes | `4003` | Change only if the local port is already occupied. |
| `task_source.provider` | Yes | `local` | Use `local` for Curator output; use `huggingface` for a published dataset. |
| `task_source.local_block` | For local | `curator` | Choose `curator`, `terminal-curator`, or `external`; omission alone defaults to curator. |
| `task_source.terminal_tasks_dir` | For terminal | `../terminal-curator/artifacts/tasks` | Path to the terminal producer publication and manifest. |
| `task_source.dataset_name` | Except terminal | `../curator/artifacts/merged_swe_tasks` | Change to another local task directory or dataset id. |
| `harbor_job.n_concurrent` | Yes | `8` | Tune for endpoint capacity, Docker capacity, and API rate limits. |
| `harbor_job.n_tasks` | No | `40` | Use `5` or `10` for smoke runs; use `null` to run all staged tasks. |
| `harbor_job.max_retries` | Yes | `2` | Lower for fast checks; raise only for unstable infrastructure. |
| `harbor_job.timeout_multiplier` | Yes | `5` | Increase when agents time out on valid tasks. This is a multiplier, not seconds. |
| `agent.name` | Yes | `custom-claude-code` | Switch coding scaffold. Change the full agent row together. |
| `agent.version` | Yes | `2.1.118` | Must match the selected scaffold and runtime image tag. |
| `agent.runtime_image` | Yes | `docker.io/jierun/c-cc-2.1.118:v0.1` | Must match the selected scaffold and version. |
| `agent.runtime_host_path` | Recommended | `artifacts/agent-runtime/claude-code` | Use the pre-extracted runtime path when available. |
| `sft_conversion.enabled` | Yes | `true` | Keep `true` when Trainer will consume Tracer output. |
| `sft_conversion.scaffold` | Yes | `auto` | Keep `auto` for fresh runs; set explicit key when reconverting old jobs. |
| `sft_conversion.tokenizer_name` | Yes | `Qwen/Qwen3.5-35B-A3B-Base` | Align with the Trainer base model. |
| `sft_conversion.max_instances` | No | `null` | Cap conversion for quick checks; `null` converts all successful rollouts. |
| `env_extra.HARBOR_EXCLUDE_TASKS` | No | `excluded_tasks.txt artifacts/processed_tasks.yaml` | Add task ids or files to skip known-bad or already processed tasks. |
| `meta_info.resources.ip` | No | `local` | Set a host/IP when Tracer should run on a remote Docker node. |
| `meta_info.resources.user` | For remote | `null` | SSH user for the remote node. |
| `meta_info.resources.directory` | For remote | `null` | Tracer block working directory on the remote node. |
| `meta_info.resources.public_storage` | No | `null` | Optional public artifact location for dashboards or sharing. |
